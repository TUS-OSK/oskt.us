# 構想: サイト上でページを編集する(保留中)

2026-11 に出た案。いまは保留で、後でやる。いまの編集手段は、GitHub の画面から直す(`_teams/README.md`)のと、Discord で秘書ちゃんに頼むサイト編集の2つ。

## やりたいこと

- サイトに Discord でログインし、Clearance LV2 以上の部員なら、サイト上でそのままページを直せる
- できれば Notion のように、表示された状態のまま書けるブロックエディタにする

## 今あるもので使えるもの

| 必要なもの | 今あるもの |
|---|---|
| Discord ログイン | 入部ページ(`pages/pay/index.tsx`)の Discord OAuth |
| LV2 以上かの判定 | 秘書ちゃんの `src/permissions.ts` にある Clearance LV2・LV3 のロール ID。サーバー側でギルドのメンバー情報(ロール)を見て判定する |
| GitHub への書き込み | 秘書ちゃんのサイト編集用 GitHub App(osk-hisyochan-site-editor)と、PR を作る処理・編集してよいパスの制限(秘書ちゃんの `src/siteEdit.ts`) |
| 見た目の確認 | PR ごとのプレビュー(`.github/workflows/pr-preview.yml`) |

## 足りないもの

1. **受け口のサーバー**: 秘書ちゃんは Web からのリクエストを受けないので、入部ページの支払いと同じく AWS Lambda を1つ作る。中身は「ログインした人が LV2 以上か確かめる → GitHub App で PR を作る」だけ
2. **編集画面**: `/edit` のようなページ

## エディタの候補

- **Milkdown(Crepe)**: 本命。中身が Markdown のまま WYSIWYG で書け、ブロックのつまみや「/」メニューもある。保存したファイルが崩れにくい
- **BlockNote**: 見た目は一番 Notion に近いが、Markdown との相互変換で書式が落ちやすく、既存ファイルを開いて保存するだけで差分が出やすい
- ファイル冒頭の YAML(班の名前・曜日など)はエディタで書かせず、ふつうの入力欄にする

## 気をつけること

- 昔の記事にはツイートの埋め込みなど生の HTML があり、ブロックエディタで開くと崩れる。最初は固定ページ・班のページ・新しい記事だけを対象にする
- 保存はいきなり反映せず、PR にしてプレビューを確かめてからマージする。GitHub App は master の「承認1件が必要」を飛ばせる設定なので、人の承認を通すかどうかを決めておく

## 規模の見積もり

Lambda・ログイン・編集画面・プレビューへのリンクまでで数日。まず班のページ(`_teams/*.md`)だけを対象にした小さい版から作るのがよい。
